## 目指しているゲーム
Web版を先に育てる。ひとつの盤面で食物連鎖と爽快な合体・連鎖を楽しみ、象への到達とハイスコアを目指す。
操作と世界の時計は独立。配置した手札はすぐ補充。Startを押すまで時計は止まる。
進行順は 芽→草→ウサギ→キツネ→シカ→シマウマ→バッファロー→オオカミ→クマ→ライオン→トラ→ゾウ。
季節はなし（2026-10-22）。手札の動物の割合は時間とともに直線的に増える：ウサギは最初から、キツネは25tickから、シカは50tickから混ざり始め、125tickで後半の配分（ウサギ18・キツネ21・シカ36％、植物25％、草は常に15％以上）に達する。シマウマ発見時は75tick相当まで進める。配布はシカまでで、シマウマ以上はすべて合体で育てる。ルール版は23。合体の着地点は連鎖できる場所を最優先し、連鎖できなければ強い動物の隣を優先する。
ゾウはスイカゲームのスイカのような位置づけ：めったに届かないが、届けば200万生点の大当たりと全画面のお祝い。オオカミ〜トラは2頭目を待てるよう空腹の猶予が2倍。
世界の25tickごとにStage 1〜8と進み、石の頻度・合体/捕食の生点倍率（×1〜×8）が上がる。植物の寿命は時間で滑らかに短くなる。（画面上の「Level」は発見段階の表示で、Stageとは別物）
現在のバランス検証と未確認点は `docs/balance-v16-verification.md`。
象は合体で生まれた動物を食べる特別なルールで、空腹速度250%、捕食点400%。
スコア表示は10000に近づく曲線と6段階の称号。過去の点数・版番号は履歴と区別する。

## 開発方針
- 会話は日本語、ゲーム内の表示は英語。
- 食物連鎖・爽快感に沿うローカル調整、実装、検証は都度確認なしで進めてよい。
- 公開、費用発生、広告・購入の有効化は別途確認。コミット・pushは明示依頼まで行わない。
- 到達可能というだけで「面白い」と断定しない。実測と仮説を分け、本人の試遊を判断に反映する。
- 動物の間の隙間は配置の要素として残す。植物を枯らして周囲の合体で除去する既存の立て直し方を維持する（2026-09-28決定、詳細は DEVELOPMENT）。
- 作業が終わるたびに PROGRESS を更新し、決定した方針は DEVELOPMENT に反映する。

移行時点の画像実装: ウサギ・キツネ・オオカミ・クマ（親子）。クマの最新作業も含めて取り込み済み。

## 初回の3手練習（2026-10-18）

初めてのプレイヤーはPLAYから時間制限のない練習へ。芽の合体 → 草からキツネへの2連鎖 → 空腹ウサギへの給餌を、それぞれ1配置で体験する。光るマスと今の手札を対応させ、説明文を見せず、絵のペア・光るマス・配置結果を中心にする。長文の遊び方ページは廃止。各成功後はNextで進み、Skipでいつでも通常ゲームへ。記録のあるプレイヤーや練習済みのブラウザには自動で挟まず、タイトルの✦（Practice）から任意に再体験できる。

練習は通常の合体・捕食関数を利用するが、時計・得点・発見・実績・匿名結果統計へ反映しない。完了後は空の盤面と通常手札で新しい試合を開始する。通常ゲームの難度・配布・ルール版22は変更なし。表示はonboarding.css、実装はscript.jsのLESSONS、回帰確認はnode test/onboarding.test.cjs（npm testにも含む）。

## ローカルで開く・確認する
このフォルダで `python -m http.server 8770 --bind 127.0.0.1` を実行し、`http://127.0.0.1:8770/` を開く。
CSS/JSを変えたら `node stamp.js` で index.html の `?v=` を更新する（スマホやXアプリ内ブラウザに古いファイルを使わせないため。忘れるとルールテストが落ちる）。
ルールテストは `node rules.test.js`、試遊シミュレーションは `node sim.js 30`。
上位の到達率は `node planner.js`（並べ方を考えるボット、遅い）。お祝い演出は `?celebrate` を付けて開き、Startで確認できる。
ゲームのバランスを変えた場合は複数の操作速度で調べ、画面の変更はブラウザでも確認する。

## 保存・公開・バックアップ
保存データ互換のため `ecosystem-puzzle` という内部キーは維持。フォルダ名と別の役割なので一括置換しない。
クラウド同期のコードと公開用Supabase設定はそのまま引き継いだ。新しいURLではブラウザ保存とログイン状態は自動では移らない。
今回移したのはファイルであり、ブラウザ内のベスト記録やログイン状態ではない。
同期はログインと通信がある場合のみ。通信不可時は既存のブラウザ保存への切替を使う。
本番は上記の独立URLへ移行済み。HTMLのcanonical・og:url・構造化データも独立URLを参照する。公開状況はREADMEだけで断定せず、GitHub Pagesの実行結果と配信ファイルを確認する。
独立したGit管理・origin登録・mainへのpushを実施済み。旧Git履歴は元リポジトリに残る。
